[Molab compute guide](https://docs.marimo.io/guides/molab/#compute).
- The **first notebook section** is dataset preparation and exploratory preprocessing, before model construction or training. We will load the labeled **iWildCam-WILDS** dataset through the WILDS interface, inspect the official `train`, `val`, `test`, `id_val`, and `id_test` split definitions, examine example **training/validation** images and image sizes, map class IDs to names (including any `empty` category), and summarize class frequencies and camera-location distributions. This is to understand the task and build a correct input pipeline, **not to re-audit or relabel WILDS's dataset**. WILDS provides the loaders, metadata, split definitions, and evaluator. [WILDS getting started](https://wilds.stanford.edu/get_started/); [iWildCam task](https://wilds.stanford.edu/datasets/#iwildcam).
- We will preserve WILDS's official splits. The notebook will use training data for training, validation data for model/parameter choices, and test data for final evaluation only. Its final output must be **one image-level class prediction per photo**, matching the WILDS classification task and evaluator. Location metadata will let us compare familiar versus unseen camera locations.
- **Architecture decision: use an integrated YOLO-World-like model.** Its YOLO-style detector learns localized visual features and scores candidate regions against CLIP-derived species/class embeddings *within the detector*. We will **not** run a separate CLIP image encoder on crops produced by YOLO. The evaluated output is still one WILDS image-level class prediction. Our initial box-to-image rule is specified below. [YOLO-World paper](https://arxiv.org/abs/2401.17270).
- This is a **supervised classification task**. The existing WILDS species names/IDs define the output vocabulary. We want the integrated model to **learn or adapt class embeddings/prompts from labeled WILDS training images**, so its visual features align with those known classes and it predicts the corresponding class ID for a new image. CLIP's text encoder does not invent new written species names; it represents supplied names or learned prompts as vectors. The exact trainable prompt mechanism and image-level loss remain model-design decisions for a later point. [CLIP paper](https://proceedings.mlr.press/v139/radford21a.html); [prompt learning](https://arxiv.org/abs/2109.01134); [YOLO-World prompt embeddings](https://github.com/AILab-CVC/YOLO-World/blob/master/docs/prompt_yolo_world.md).

### Practical constraint to resolve while preparing the notebook

WILDS describes iWildCam as **image-level multi-class classification**, not a box-labeled detection benchmark. One label per photo does **not** guarantee exactly one animal or tell the model which candidate box is an animal. A pretrained integrated detector may propose false boxes, including on empty images; image-level supervision alone does not directly teach it the correct box count or locations. We will evaluate false proposals as a possible failure mode rather than hard-code a one-box assumption. If we later fine-tune a detection head with a box-supervised loss, we must specify where its box targets come from or choose a training approach that uses the available image labels. We will resolve that under the model/training point; it is **not a demand to verify WILDS's annotations ourselves**. [WILDS iWildCam problem setting](https://wilds.stanford.edu/datasets/#iwildcam); [YOLO-World fine-tuning data format](https://github.com/AILab-CVC/YOLO-World/blob/master/docs/finetuning.md).

**Baseline box-to-image rule (agreed):** Run the integrated model with WILDS animal-class prompts; assign the image the class of its **highest-scoring detection**. If there is no detection, or its score falls below a threshold selected on validation data, predict the WILDS `empty` class. This yields exactly one image-level prediction. False high-scoring boxes are an explicit baseline failure mode. We can evaluate a pretrained model with this rule before adapting it to WILDS.

**Training decision still open:** To fine-tune the integrated model on WILDS image labels, we still need an image-level training objective and a decision about which components to train. Standard YOLO-World box-supervised fine-tuning cannot be applied directly to WILDS's image labels. We will settle this under the model/training point, using validation rather than test data for design choices.

The user will confirm dataset loading and available capacity in their Molab environment during notebook execution. We will record the observed result then; dataset capacity is not an unresolved design choice for this plan.

## Notes for the next point - Candidate training baseline (not yet finalized)

- **Research contribution to test:** Both YOLO-World and YOLIP are designed around region/box-level predictions and supervision, whereas iWildCam-WILDS provides one class label per image. Our project will study how to adapt an integrated vision-language detector to that image-level supervision and evaluation, including `empty` images, without pretending WILDS supplies box labels. The proposed max-over-regions image-level loss is a candidate adaptation, not yet a claim of a novel loss or state-of-the-art result; its value must be established by comparison with simpler baselines and prior weakly supervised approaches.
- **Recommended trainable components:** Start from pretrained YOLO-World. Freeze its image backbone, vision-language fusion, box regression/localization, and CLIP text encoder. Initialize one WILDS animal-class embedding from each class-name prompt, then train only these class embeddings and, if needed, a small shared score scale/bias. This keeps the detector's localized features inside the integrated model while making the supervised adaptation small and feasible without box labels.
- **Recommended image-level objective:** For each animal class, take its highest score across the model's candidate regions as that image's class score. Give the `empty` class a separate score/threshold; apply image-level cross-entropy against the WILDS label. At inference, this corresponds to the agreed highest-scoring-detection rule, with `empty` when no animal score clears the validation-selected threshold. Use candidate scores before hard detection filtering so the image-level loss can train the class embeddings. Confirm the actual label mapping and model interface during implementation.
- **Reference and next experiments:** Evaluate frozen, prompted YOLO-World first as a no-training reference. Compare it with the trained-embeddings baseline. Later options to revisit are unfreezing the detector's semantic head or fusion layers, replacing hard maximum aggregation with smooth/attention pooling, or using carefully checked pseudo-box supervision. None of these extensions is committed yet; box-supervised losses still require box targets.
